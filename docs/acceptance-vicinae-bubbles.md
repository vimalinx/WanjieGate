# Vicinae 意图泡泡桥接验收

日期：2026-09-27。实现与验收：本会话 Codex。用户已明确停止 brainstorming，授权自主开发与测试。本记录不推定双方具名共识。

## 交付位置与范围

实现位于独立工作树 `codex/vicinae-bubbles`。基础为 `codex/bubble-demo` 的 739c3a2，加上用户指定的 5174 页面对应 backend、static、tools、docs/licenses 源码快照。原工作树及其 5174 服务未修改；既有透明薄膜材质、玻璃渲染与动效不是本次新创作。

本次在万界门项目内新增：

- `backend/vicinae.py`：实时目录发现、6 个明确用途入口、参数数组调用、执行前再校验与未知结果反馈，通过现有 Runtime 权限和任务受理执行。
- `static/js/bubbles/execution.mjs` 和 app/state/client：实时候选、版本校验、双击执行、拖拽组合与真实产物展示；不同输入的同名动作独立运行，同一输入重复双击去重。
- `static/launcher.css`：在指定画风上加入搜索框磨砂与桌面尺寸适配；按用户最新要求移除框外整块底板。
- `integrations/vicinae/`：macOS 透明 NSPanel + WKWebView 原生窗口、构建/启动/安装脚本。

已安装本项目脚本 `~/.local/share/vicinae/scripts/wanjiegate-intent.sh`，Vicinae 命令 ID 为 `scripts:wanjiegate-intent.sh`，显示名称“万界门 · 意图泡泡”。应用产物位于工作树 `.data/native/Wanjie Intent.app`。服务为 `http://127.0.0.1:5175/launcher`，数据在独立 `.data/vicinae-preview`。

当前接入方式是 Vicinae 命令唤起万界门原生透明浮层，再把匹配的桌面操作交回 Vicinae。尚未替换 Vicinae 原有主搜索框或修改其 fork 源码，不能称为原生主搜索 UI 合并完成。

## 回归方式

```sh
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
HAPPY_DOM_MODULE="$PWD/.ai/test-deps/node_modules/happy-dom/lib/index.js" \
python3 tools/selftest.py
```

最终回归执行 84 个 Python 用例，83 个通过、1 个环境前提不满足而跳过；所有 JavaScript 回归与两套 DOM 测试通过。

新增 Python 桥接测试覆盖实时目录筛选、命令消失、查询参数不进入 shell、超时结果不明、桌面入口不可假装数据源、权限与重复命令去重。新增 DOM/状态测试覆盖单击不执行、双击恰好执行一次、保存版本、清空输入、晚到结果、同名动作跨输入重新运行。原 Demo DOM 的融合、取消、超时、撤销、减少动画与工具交接回归一起执行。

首次基线的 7 个 HTTP 用例报 502；对本机地址设置 NO_PROXY 后通过，未为此改变产品网络策略。Python 隔离执行用例因本机缺少 Linux bubblewrap/prlimit 跳过，范围与本次桌面桥接无关。

曾在实测中发现并修复组合运行保存顺序造成版本冲突，以及同名动作错误复用前一次输入结果；两者均先复现为失败 DOM 测试，再修复。

## 已知边界与交接

- 首版只有 6 个桌面入口，不自动导入未知扩展的执行权限。浏览器标签页仍依赖 Vicinae 浏览器连接配置。
- 已组成的旧输入组合会保留但禁用执行，需拆开或清空后按新输入重组；运行中任务使用冻结快照。
- 社交为草稿与发布编辑器交接，不是自动发帖，未验证其他平台发布接口。模型草稿仍需审阅，不能以生成成功证明事实正确。
- 命令唤起参数只保证首次打开面板时使用；面板已打开时会激活现有窗口，用户可直接在窗口内编辑。
- Jev/生成密钥只从已有服务端 env 文件读取；源码、前端和文档未复制密钥。
- 原生主搜索框替换需 Vicinae fork 的 owner 接手。注册项目归属/owner 为 unknown；根协调者需要确定 owner 和是否采用本项目桥接接口。本次未修改外部注册项目、未向其他聊天发送消息。

## 搜索入口收口（2026-09-27）

用户补充要求主界面按 Vicinae 的快捷键搜索方式调用，随后要求只保留搜索框、去掉周边一圈。现已移除原生窗口的整块磨砂视图、网页根背景及框外提示；空输入收缩到搜索框，输入后扩大透明承载区域，泡泡独立环绕。齿轮内保留设置、产物、添加资料及普通命令搜索。

Carbon 注册 Control + Option + Space；NSPanel 浮于普通窗口之上，支持全部空间和全屏辅助窗口，唤起聚焦输入。Esc 的原生日志实测为 `hidden visible=0`，窗口再次唤起保留进程和画布。CUA 读取窗口会重新激活应用；其定向按键未取得全局 Carbon 回调证据，因此全局快捷键的跨应用物理按键行为尚未实测，不把程序化重新激活算作热键验证。Swift 编译和最新 DOM 回归通过，原生截图确认空输入只有搜索框、输入后出现真实 Jev 候选。未配置开机自启。

## 应用启动遗漏修复与磨砂展开（2026-09-27）

用户反馈“帮我打开微信”没有泡泡。根因是本项目桥接仅筛选六个固定命令，漏掉 Vicinae 实时目录的 `applications:*` 条目；直接观察到 `applications:com.tencent.xinWeChat` 已存在。新增应用名称与英文标识检索候选，由 Jev 判断是否适合当前意图；执行前重新确认条目仍在真实目录，只启动应用且不转发查询参数，不读取应用内容或发送消息。当前目录 227 条，支持 6 个原入口和 124 个应用启动入口；候选仅召回当前输入提及的应用，不等于对全部命令开放执行。

新增用例先复现微信候选为空，再覆盖中文/英文匹配、应用启动不转发参数和不存在的应用拒绝执行。实际原生窗口输入“帮我打开微信”后出现“打开微信”泡泡，运行结果显示 Vicinae 已受理；不以受理反馈证明微信内任何操作完成。最新回归 85 个 Python 用例，84 通过、1 环境跳过，JavaScript 与两套 DOM 测试通过。

按用户新反馈，空闲仍仅搜索框；输入展开时显示原生 NSVisualEffectView 磨砂面板，增加泡泡边缘与文字对比度，并显示候选等待、授权/错误及空结果提示。原生截图已核对。替代上一版展开状态无底板的视觉选择，历史需求保留。
