## 布局与操作

搜索框保持在视觉中心，周围扩展为同一启动器窗口内的磨砂区域。泡泡使用透明或低透明度底色、清晰边界与可读文字。透明度不能降低文字可读性。桌面背景模糊依赖原生窗口能力；网页阶段的 CSS 模糊仅验证视觉，不算已实现桌面磨砂。

原有命令搜索继续可用。输入法组词、普通输入和候选操作不抢焦点。建议默认最多同时显示 6 个泡泡；候选沿用稳定位置，通过加入、更新、移除反映新判断，不持续随机漂移。该数量为 Codex 初值，可由实测调整。

- 单击：选中并展示目标、参数或组合步骤，不执行。
- 双击：启动当前动作或组合。缺少参数时打开补充面板。
- 拖拽重叠：预览并建立类型兼容的组合，不执行。拖动结束不能触发双击处理。
- 键盘：选中后 Enter 执行，提供合并操作作为拖拽替代。
- 运行中：显示步骤状态，可停止后续步骤。重复双击复用同一 runId。

候选默认随输入更新，不默认新增跨会话固定功能。拖拽期间暂缓候选布局变化，松手后使用最新输入重新校验。尚未执行的组合保留成员快照，但输入变化后标记待校验；不再适用时禁用并说明原因，不静默换掉成员。明确清空输入时清除临时候选与未运行组合。已启动任务使用冻结输入，结果保留在任务记录，不随候选消失而丢失。

## 实时 Jev 判断

实时指不需要按回车提交。建议首版以 150 毫秒合并输入事件，最多一个判断请求在途，同时只保留最新待判断文本。中文组词结束后才进入判断。150 毫秒是调度初值，不是已测推理延迟；记录端到端延迟后再调整。

每个请求绑定 sessionId、inputRevision、catalogRevision 和上下文引用。输入变化立即标记旧候选待更新；旧候选不能执行旧参数。只接受与当前版本匹配的响应，清空输入、关闭入口或切换 Intent 后使旧响应失效。

从已登记且可用的候选中判断相关性，可以返回多个候选或无匹配。Jev 负责判断，程序负责命令 ID、参数、类型和权限校验。模型不能生成任意 shell 命令。复杂正文交给独立生成能力，不能假定 Jev 提供文本生成。

候选召回先覆盖首版人工补充语义信息的小目录；扩容后再评估索引与召回。新命令仅有名称时标记元数据不足，不向用户承诺未声明的动作。Jev 故障时显示不可用，保留普通命令搜索，不用关键词规则冒充 Jev。

## 目录、组合与执行契约

以下字段为拟新增契约，不表示已有 API：

| 对象 | 必要信息 |
|---|---|
| 能力 | capabilityId、provider、commandId、title、description、inputSchema、outputTypes、launchMode、availability、effect |
| 泡泡 | bubbleId、capabilityId、inputRevision、boundInputs、missingInputs、status |
| 组合 | compositionId、revision、成员 ID/版本、步骤依赖、输入输出绑定 |
| 运行 | runId、Intent、冻结参数、组合版本、Task、执行反馈 |

Vicinae 清单是实时存在性依据；参数、语义说明和结果类型由经过核验的适配描述补齐。调用前复核命令仍存在，CLI 通过参数数组启动，不拼接 shell 文本。桥接服务沿用本地 Runtime 的命令校验与授权，不暴露无鉴权的通用执行端点。

资料到动作、动作到动作仅在输出可绑定到下游输入时合并。首版最多 3 个顺序步骤，不支持循环。只能打开界面的命令标记为 handoff，不能假定返回文件、行情或已发布帖子。

状态分别为待补参数、可运行、运行中、已打开待继续、完成、失败、结果未知。CLI 受理成功最多证明启动已受理；业务完成需要提供者证据。结果未知先核对，不自动重试可能重复产生副作用的动作。

## 首版场景与推进顺序

| 阶段 | 交付与完成标准 |
|---|---|
| 桥接验证 | 使用万界门现有服务验证 Jev 实际判断、实时泡泡、双击和合并；至少一个真实 Vicinae 入口可启动。此阶段不宣称已嵌入原生搜索框 |
| 原生整合 | Vicinae 搜索框输入事件接入同一语义服务，原生窗口呈现磨砂区域和透明泡泡；原搜索、焦点与快捷键仍可使用 |
| 场景验收 | 调研、股票、社交媒体分别完成以下流程，区分完整执行和人工接续 |

调研：先支持已有资料、指定网页链接和真实搜索入口；网页搜索入口只显示已打开。读取到正文后，才能与总结动作组合。通用联网搜索结果 API 尚未接入，不能冒充已检索证据。

股票：复用万界门行情适配，明确证券代码、市场、来源与报价时间；与研究卡片动作组合。无有效行情时显示失败或历史报价状态，不伪装实时数据。本轮不包含交易。

社交媒体：支持材料到草稿再到发布入口的组合。首版在未核验账号和发布提供者之前，执行到草稿及打开发布编辑器；这属于接续流程，不能称为自动发布已实现。后续接入真实发布时，泡泡展开后展示账号、平台和实际正文，再由用户双击明确的发布动作执行，保留帖子 ID 或链接作为完成证据。用户讨论社交功能不构成本会话代发帖的授权。

上述场景为产品范围；第一条技术验收建议用本机已存在的文件搜索入口验证，随后完成股票卡片和社交草稿。不能用此临时技术样例替代三个业务场景的验收。

## 实施归属

万界门负责动态能力描述、Jev 适配、候选/组合状态与 Runtime 执行接口。本项目可以实现和验证这部分。

Vicinae fork 负责搜索输入事件、磨砂窗口、透明泡泡原生渲染以及必要的结果回传。其注册项目和 owner 当前 unknown；应由 VimalinxOS 根协调者确认并分配，不在万界门工作区越界修改外部注册项目。本规格可作为接口交接材料，尚未向其他聊天发送消息。

## 验收

1. 输入过程中出现真实 Jev 候选，无需回车；改口、否定、清空和中文输入法不出现过期结果。
2. 单击不执行；双击恰好创建一次运行；拖拽结束不误执行。
3. 泡泡更新不打断拖拽，不改写已运行任务；旧参数不能在输入改变后继续执行。
4. 兼容组合传递真实对象与全部绑定；不兼容组合保留原泡泡并解释原因。
5. Vicinae 目录读取、启动受理、界面打开和业务完成分别提供证据。
6. Jev/命令提供者不可用时明确失败；股票保留来源时间；社交接续不显示已发布。
7. 原生阶段验证文字可读、磨砂、焦点、Esc、键盘和原有命令搜索；网页通过不代表原生通过。

验证计划：先做候选版本与单次执行的自动化检查，再实测少量中文场景和真实命令，最后做原生视觉与焦点检查。当前已完成的仅为本机版本、CLI 帮助和命令目录只读探测，未调用 Jev、行情或发布接口，也未完成上述产品验收。
